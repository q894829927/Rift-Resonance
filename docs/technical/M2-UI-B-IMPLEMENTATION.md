# M2-UI-B：像素清晰度与视觉比例修复

基线：`codex/m1-art-cc0-bootstrap` / `0cd1753`（M2-UI-A）  
范围：**仅客户端渲染与美术表现**。不改变 960×540 逻辑战场、服务端物理碰撞、伤害、刷怪、20Hz Tick、10Hz 网络投影、升级或结算规则。

## 一、主要问题与处理

| 原问题 | 根因 | M2-UI-B 调整 |
|---|---|---|
| 角色、怪物边缘发虚 | Phaser `pixelArt: false`，纹理线性滤波 | 启用 `pixelArt: true`、`antialias: false`、`roundPixels: true`；仅游戏 Canvas 使用 `image-rendering: pixelated` |
| 原图像素分布不均匀 | 部分 Sprite 缩放为 2.15、2.5、4，且环境装饰使用 0.77～1.6 浮点倍数 | 角色、怪物、地形装饰与瓦片缩放使用统一正整数倍数，见下表 |
| 人物冲刺/受击时可能透明或闪烁 | Dark World 128×192 图集第 2/3 帧是透明帧，但旧代码把它们映射为受击/冲刺 | 使用图集 12～23 帧，分别对应正面/背面/侧面四帧循环；冲刺和受击只改变染色，不再切换到空帧 |
| 场景颜色太暗、地板层次不足 | 地砖纹理明暗差距偏小 | 提升低反差石砖、裂纹与边界亮度；保持无遮挡的中心战场 |
| 角色和敌人可见轮廓不一致 | 独立设置了临时小数显示倍数 | 正式使用显式比例常量，保持怪物层级区别，不改变敌人半径 |

## 二、源图与显示比例

| 美术类型 | 原始源图/帧 | 游戏世界绘制比例 | 说明 |
|---|---:|---:|---|
| 玩家 Kaishido 动画帧 | 32×32 | 3× | 图片帧 96×96 世界像素，实际非透明角色小于该尺寸 |
| Kenney 普通怪 | 16×16 | 3× | 48×48 世界像素 |
| Kenney 大型怪（狂暴兽占位） | 16×16 | 6× | 96×96 世界像素；只是占位资产的可视大小 |
| Dark World 树/石/蘑菇 | 原生完整 PNG | 1× | 保持源图清晰且不压住战场中心 |
| Dark World 16×16 瓦片 | 16×16 | 2× | 拼接边缘装饰，原始图集仍不参与整图平铺 |

统一常量与方向帧算法在 `apps/client/src/art/m2PixelPresentation.ts` 中。**视觉尺寸不等于碰撞体积**；服务端仍使用原有碰撞半径和游戏规则。后续更换正式素材时要重新校准脚底锚点和攻击预警范围。

### 关于相机与清晰度

- 仍使用 `calculateCameraZoom(w, h)` 将固定的 960×540 世界完整映射到真实浏览器视口。不会为了让素材变大就将世界尺寸缩到 640×360，导致敌人或客户端姓名位置错位。
- 对像素纹理采取 nearest-neighbor，消除**线性滤波引发的模糊**；而在 1366×768 等无法实现严格整数最终缩放的视口上，仍可能出现像素宽度不均匀，这是保持完整视野及响应式布局的折衷。
- 仅靠 3×、6×放大**不会创造更高原始细节**，只有后续正式高分辨率人物/怪物资源才能进一步减少“大像素块”感。
- 高分辨率 Kenney 烟雾/粒子仍作为表现性视觉特效，可继续使用非整数缩放，它们不属于本次强制整数倍的角色、怪物和地图 Sprite。

## 三、修改范围

- `apps/client/src/main.ts`：Phaser 游戏配置最近邻渲染；保留摄像机世界适配及 DOM 投影。
- `apps/client/src/style.css`：只对 Canvas 使用 pixelated CSS，不损失 HTML HUD 字体清晰度。
- `apps/client/src/art/m1Visuals.ts`：修复空白帧映射，设置可读的玩家/普通怪/大型怪尺寸、脚底阴影和血条高度。
- `apps/client/src/art/m2PixelPresentation.ts`：统一缩放常量、角色四方向有效帧算法。
- `apps/client/src/art/m2ArenaBackdrop.ts`：整数倍贴图与地板对比度微调。
- `tests/ui-pixel.test.mjs`：验证像素渲染配置、缩放常量、空帧规避与 Dark World 原图尺寸。
- `.github/workflows/m2-ui-a-verify.yml`：同时运行 `npm run verify`、布局测试和像素测试。

## 四、验收与后续

CI 检查含 TypeScript/Vite 构建、单测、布局规则以及原始 PNG 尺寸检查。基础浏览器视觉截图仍需实际运行时复核：

1. 1366×768、1600×900、1920×1080：角色不透明消失，像素边缘清晰，UI 层始终可读；
2. 四方向走动、冲刺、受击、死亡时帧动画、阴影与血条位置一致；
3. 两类怪物的视觉占比可辨识，注意大型占位怪可能超出服务端碰撞体积；
4. 暗色地板不再糊成一片，不和攻击范围/警示箭头争夺视觉焦点；
5. 多人/升级弹窗、玩家名牌在缩放前后仍正确对应服务器坐标。

**暂不进行：** 修改服务端坐标或碰撞范围、直接生成 AI 素材、强制缩小可见战场、F-09/F-10 和长期性能验收。地图及怪物像素资产的“真实细节上限”仍属于后续统一美术制作阶段。
