# V0.1.2 跨设备响应式布局与触屏操作

目标：不更改已部署的 1440×810 服务端权威世界，把可见舞台、UI 与移动输入适配不同设备。

## 规则

- 固定世界：逻辑坐标仍为 1440×810；摄像机采用 `calculateCameraZoom` 的 contain 适配，不能单凭设备尺寸改变角色碰撞、敌人生成和武器距离。
- 宽屏：尽可能放大完整舞台，但同时限制舞台高度以免网页纵向滚动；21:9 留出环境背景边缘，不拉伸地图。
- 平板：按钮、标题、房间面板按场景尺寸适配，不依赖桌面硬编码像素坐标。
- 手机横屏：压缩顶部信息，地图优先；粗指针设备在战斗 RUNNING 阶段显示方向键+冲刺。
- 手机竖屏：完整显示横向地图（因此画面更小），把方向键和冲刺置于地图下方；竖屏可操作，但推荐横屏以改善角色可辨识度。
- 房间面板：窗口高度不足时启用独立滚动，输入框、复制房间码、武器确认和准备按钮须可达。
- 升级和结算：窄屏竖排升级选项，面板内部滚动；暂停升级期间不允许触屏移动。
- 输入：键盘输入和虚拟方向键按下状态取并集；`pointerup`、`pointercancel`、`lostpointercapture`、窗口失焦必须释放；多指可组合方向键和冲刺。
- 采用 `viewport-fit=cover` 和 CSS `env(safe-area-inset-*)` 避开圆角/刘海设备不安全区。

## 手动验收（自动 CI 不能替代真实浏览器）

1. Windows 桌面 1920×1080、1366×768 和浏览器缩放 80%/125%；画面完整、无侧边栏、标题和模式按钮居中。
2. 21:9 2560×1080 和 4:3 平板：世界纵横比不变，无角色视觉错位或 HUD 越界。
3. iPhone/Android 竖屏 390×844：菜单按钮、多人房间创建加入和滚动、单人进入战斗、触屏方向键和冲刺可操作。
4. 手机横屏 844×390：横向舞台尽量占满可用空间，触屏按住可持续移动，多指对角移动和冲刺正常。
5. 进入升级面板后方向键不遮挡选择；断线/切后台/手指离开时不持续移动；重复进入游戏不会残留触摸状态。
6. 浏览器开发工具检查 WebSocket 同步，无前端 JavaScript 错误；ECS 部署后 `/health` 版本与右上角 `v0.1.2` 一致。

本次主要修改客户端响应式布局和触屏控制。未增加服务端输入类型或修改游戏物理规则。
