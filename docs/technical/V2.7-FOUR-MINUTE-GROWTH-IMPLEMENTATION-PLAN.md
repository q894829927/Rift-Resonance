# V2.7 四分钟火力成长与升级池｜分阶段技术实施计划

> **状态：技术落地方案，未写入生产游戏代码；规则以 [V2.7 策划](../design/V2.7-FOUR-MINUTE-SURVIVOR-PROGRESSION.md) 为准。**  
> 当前开发基线 `v0.1.5`、`codex/v2-dual-weapon-foundation`，仅 `dual_v2` 生效。严格保留 `legacy` 与现有两武器选择规则。

## 0. 目标、边界与版本策略

- 不修改 `SpawnSystem` 的任何怪物生成频率、刷怪位置、狂暴兽生成比例、两类敌人的生命/移动速度/伤害、最多 60 只活体和 4 分钟模式终点。
- 继续服务器 20Hz 固定时间推进、客户端 10Hz 状态、升级手动选择。服务端控制职业与数据流，不能为了特效更热闹去添加客户端裁决。
- 每个代码实现阶段都提交单独的**常规 feature 版本**，按 `AGENTS.md` 用版本脚本写版本和 `CHANGELOG`；本文是纯文档不升级版本。
- 先提供 benchmark 报告与自动化测试，**后**逐步合入数值和新卡；不能仅靠 CI TypeScript 通过就断言“后期割草达标”。

## 1. P0｜先建立量化基线（纯测试）

新增确定性 240 秒基准测试/离线跑分脚本：
- 100 个固定种子，1/2/4 玩家，四种 `fireball×void` 分支配对；严格复用当前 `dual_v2` 敌人定义和刷怪配置。
- 自动化玩家只做可控的移动及**合法卡选择**，每次选择都仍通过服务端升级 API；统计每次选择、落后/超前构筑，不把 bot 当真实玩家表现。
- 记录开局/60/120/150/180/210/240 秒的真实刷怪量、清怪量、场上剩余 HP、活体上限命中次数、有效命中率、弹幕并发、VFX 网络字节数、Tick 运行时间、伤害事件是否溢出。
- 输出基线图表和 `JSON` 报告，禁止先修改敌人以让目标自动变好。

## 2. P1｜经验节奏与抽卡架构

位置：`packages/simulation/src/combat/progression.ts`、`world.ts`、`types.ts`；客户端仅复用现有三选一卡 UI：
1. 将 XP 规则单独集中到 `V2GrowthConfig`：首级 35，后续 50/65/85/100/120/145/170/195…，保留多人倍率与普通怪 5/狂暴兽 12 经验。
2. `matchElapsedTicks` 为保底基准；在 65/125/185/210 秒按一次性状态标记最多补足一个下一等级 XP，不产生自动卡选择。需要加入`upgradeReady` 重算，避免 XP 溢出后没有击杀就无法再次升级；手动选择完成后逐步触发下一次升级，绝不堆叠多个同时弹窗。
3. 类型层新增两武器共享的正规升级注册表（`weapon_branch` / `weapon_power` / `rune` / `weapon_mastery` / `dual_boon` / `awakening`），服务端只从当前合法注册表生成可选卡；每张卡的 `id` 固定，禁止新旧 ID 意外共存。
4. 分支二选一、III、共鸣、觉醒按固定优先级保底，剩余槽按 RNG 权重填写，每次三张且不重复；已持符文和未持符文按不同槽位逻辑处理；第一次/下一次重抽只替换合法未选卡，不恢复限时自动选。
5. 玩家新局和重赛必须重置所有新增符文等级、精进、共鸣、觉醒、软保底标志；断线重连可完整读取当前结果。
6. 测试：1/2/4 人手动升级、RNG 重演、非法卡拒绝、槽位上限、选项去重、前置满足/不满足、200 Tick 升级暂停时计时冻结、多人独立奖励。

## 3. P2｜有效弹幕覆盖和两分支独立成长

位置：`weapon.ts`、`damage.ts`、`types.ts`、`fireballTrajectory.ts`：
1. 实现通用符文多重施法 0/1/2 侧弹，目标应尽量不同；新弹体明确 `fireballSecondary` 标志，只有真正中央主弹触发 `split` 或 `ember`。按武器持有状态限池。
2. 贯燃弹道服务端 swept collision 按路径先后获得最多 2/3 个**不同**命中目标；第一次主弹命中触发 II 分支一次，后续仅给予递减伤害。主弹被空间锚点改向也只能按规则消耗一次改向预算。
3. 更新迅捷施法 12/22%，避免与其它缩 CD 来源超上限；保留天赋满级不重复占新的符文槽。
4. 按 V2.7 调整火种 II/III 伤害/范围/周期、同目标锁周期、剩余脉冲转换上限，所有 UI 文案和视觉圈用服务端同步的真实半径；仍禁止火种伤害再次创造火种。
5. 虚空法球活跃阶段增固定周期脉冲，保留现有奇点终结/锚点小冲击、BOSS 不能强制牵引、两场上限；按唯一场域来源决策引力位移以免叠加失控。
6. 测试：同 Tick 同敌人多弹碰撞、侧弹不能产生二次弹幕/火种、贯穿受限、非递归、火种每 10 Tick 单目标全房去重、跨玩家火种消费、正常升级暂停冻结、原 `legacy` 路径完全一致。

## 4. P3｜武器专属精进、四分支共鸣、终局觉醒

- 实现四个独立 `weapon_mastery` 效果：追猎火星、余焰爆燃、引力回响、锚点回声。III 且 100 秒后合法；每把武器一次。
- 保留已实现的 `collapse_inferno` 名称、逻辑来源，按新灼烧频率更新剩余潜力换算；新增 `ember_anchor_ignition`、`split_collapse_shards`、`split_anchor_prism`，所有分支搭配可用至少一种专属高级能力。
- 实现四个觉醒效果：星火风暴、燎原禁区、终末坍缩、星门齐射；180 秒且任意武器 III，单玩家至多一项。所有次生弹和状态派生事件显式标记 `generation`/`sourceActionId`，防止链式重入。
- 增强 `CombatEvent` 原有 64 项缓冲策略：固定优先级保留共鸣/觉醒/死亡/升级关键事件，低级普通伤害统一聚合；事实型生命变更仍通过同步状态，不能被 UI 容量剪裁改变。
- 根据是否为分裂主弹、侧弹、火种/回声弹提供只读视觉类型，客户端特效尺寸/形状区分，不要把多个服务端相同伤害对象在客户端重新随机创造命中。

## 5. P4｜稳定性/联机/性能与实玩验收

- 压力输入：单人/双人/四人、60 活怪、最多 8 火种/人、32 有效弹体/人、多个虚空场、端到端 240 秒，统计 CPU p95/p99、内存、带宽、状态包大小和事件溢出。
- 最先针对当前 ECS 2 vCPU/2 GiB 验证计算预算；如果单房处理超过预算，**优先优化空间查询、对象池、事件聚合、粒子裁剪，不能首先削弱怪物生成和血量**。
- 逐支分别验收 `split+collapse`、`split+anchor`、`ember+collapse`、`ember+anchor`；其中任何一路没有拿高级共鸣时也应在标准移动/密集敌群中形成可用输出。
- 分析 100 种固定随机种子的每阶段清怪率，必要时**只微调玩家侧数值、经验节奏、卡池权重**。验收之后才进入下一把武器 D6，不要拿新增武器来补偿现有两武器能力不足。
- 浏览器对照视频：v0.1.5 VS V2.7，60/120/180/240 秒各录 15 秒，检验“前期疏、后期密、末段成片清怪”的清晰节奏。
