# v0.1.3 单人准备、多人房间及舞台布局调整

## 范围

- 公网 HTTP 下邀请代码复制：优先使用 `navigator.clipboard`，不可用时针对 readonly 房间码输入框执行 `focus/select/execCommand("copy")`，仍失败则保持选中并提示用户手动复制。
- 单人模式：进入单人准备弹窗，填写昵称、选择两种不同武器后才能点击开始；点击后创建真实 Colyseus 房间，将所选顺序提交给服务端并等待 `loadoutConfirmed`，服务器确认后自动发送准备。不会通过绕过服务端实现本地单人逻辑。
- 当前服务端仅支持火焰弹与虚空法球组成双武器；本次只能交换这两种武器的顺序，不将其他规划武器伪装成已完成。
- 多人模式：未加入房间时，「创建」和「加入」以可切换页签出现，公用昵称字段；成功加入后隐藏表单，显示房间码复制、成员列表、双武器确认及准备；退出后恢复入口。
- 响应式布局：整套游戏壳体的宽度同时受 `100vw` 和 `100dvh` 限制，游戏舞台始终为 16:9，顶部栏/地图/页脚统一宽度并居中，触屏竖屏依然优先完整显示画面。网络世界依旧固定 1440×810，不能以 CSS 更改战斗物理。

## 测试计划

1. 公网 HTTP IP 和本地 localhost 各建一个多人房间，复制邀请码到普通聊天输入框粘贴；限制剪贴板权限后仍应能选中手动复制。
2. 单人点击入口先显示两把武器的选择与开始挑战按钮；选择重复武器时不可开始；等待服务端 `loadoutConfirmed` 后自动准备并开局。
3. 多人进入创建和加入页签切换，显示内容不重叠；创建成功后表单消失，邀请码/成员/武器/准备出现；第二台浏览器用复制代码加入。
4. 按 1920×1080、1366×768、21:9 屏幕和移动端横竖屏检查，顶部/底部栏的宽度与地图统一，没有右侧单边大片空白。
5. 已建房后退出、掉线、重连及战斗结算：没有残留弹窗或失效按钮；新版本不破坏双人联机、手动升级及服务端权威判定。
6. ECS 的 `/health` 应返回 `appVersion=0.1.3.0`；实际浏览器右上角显示 `v0.1.3`，并完成至少一次真实联机和屏幕缩放测试。

本版只改变客户端入口体验、剪贴板与网页排版，没有更改服务端战斗范围、碰撞和网络协议。GitHub CI 只能验证代码和已有自动测试，不能替代真实浏览器视觉验收。
