# M2-A 实现记录：团队共享经验与同步升级

基线：`codex/m1-art-cc0-bootstrap` / `b6b7935`  
范围：服务端权威的团队经验、等级和多人同步升级；不包含完整职业、十二被动、武器进化、Boss、F-09/F-10 或长期压力验收。

## 已完成

### 独立战斗模拟

- `packages/simulation/src/combat/types.ts`
  - 玩家初始只装备稳定 ID `weapon.fireball`，保留两个武器槽。
  - 增加武器等级、基础被动等级、团队等级/经验、升级状态和 10 秒超时字段。
  - `CombatPhase` 增加 `UPGRADING`；固定 Tick 仍为 20Hz。
- `packages/simulation/src/combat/progression.ts`
  - 裂隙虫群/狂暴兽经验奖励分别为 5/12，来自服务端敌人定义。
  - 团队经验池按 GDD 的单人 50/70/90/... 曲线计算，并按在线队伍规模使用 25% 的增量系数。
  - 敌人实体带 `experienceAwarded` 标记，击杀奖励和升级触发不会重复结算。
  - 经验达到阈值后，在当前战斗 Tick 的刷怪、AI、武器和伤害全部完成后才进入 `UPGRADING`。
  - 升级期间不推进 240 秒对局计时，不移动玩家，不运行敌人 AI、弹体和伤害；房间连接、选择消息和固定 Tick 超时仍可处理。
  - 每名在线玩家由服务端生成最多三项有效候选：解锁回旋刃、强化已装备武器、获得/强化 `passive.vitality`。候选会过滤满槽、未装备或达到原型等级上限的项目。
  - 每名玩家只能提交一次；重复、伪造或不属于该玩家候选的 ID 会被拒绝。10 秒到期时选择候选列表第一项作为确定性自动选择；离房玩家从待处理集合中移除。

## 已知限制与明确占位

- 当前只实现回旋刃解锁、武器强化和一个生命值被动；没有完整十二被动、稀有度、进化和职业系统。
- 候选生成是确定性原型池，不是最终随机池；当所有原型项目达到上限时不会发放非法候选，后续需要设计“无可用升级”的正式结算策略。
- 团队规模系数和敌人经验/刷怪节奏尚未做平衡验收；F-09/F-10 和长期性能测试继续后置。
- 升级卡片图标、正式动画和特效仍沿用已有 UI/占位表现，暂不生成 AI 美术。
- 重连期间的升级状态恢复、房主长期断线和跨局统计持久化不在本阶段范围内。
