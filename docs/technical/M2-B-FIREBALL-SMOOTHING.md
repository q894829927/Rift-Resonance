# M2-B 火焰弹弹道平滑修复

## 原因

当前 Colyseus 服务端以 20Hz 进行权威战斗模拟、10Hz 推送网络状态；客户端 Phaser 通常按显示器刷新率进行渲染。在修复前，`apps/client/src/main.ts` 的 `showCombat()` 对火焰弹、奥术弹直接执行 `entity.setPosition(projectile.x, projectile.y)`。其位置只有网络快照变化时才改变，导致在 60FPS 画面里约每 100ms 跳动一次，看起来像“一帧一帧地移动”。

回旋刃此前已有不同的 95ms Tween 处理，不在本次修复范围内。

## 修复

- 新增 `apps/client/src/art/m2ProjectileInterpolation.ts`，只对客户端视觉坐标计算插值，使用服务器同步的目标点与独立的显示轨迹；
- 初次收到投掷物时立即显示在服务端位置；下一次快照起，在约 100ms 内从**当前显示位置**线性过渡到新的服务端快照位置；
- 每个渲染帧只取插值结果；**收到重复快照不重启动画**，避免一直从头插值而出现拖尾或停滞；
- 新快照在前一次插值未结束时到达，从**实际显示位置**连续转向新目标，避免位置突跳；
- 超过 160 世界单位的异常跳变或超过 450ms 的旧轨迹更新直接吸附新坐标，避免网络卡顿后出现长距离错误飞行；
- 保留原有渲染配置（nearest-neighbor 像素画、摄像机、联机预测），也没有提高实际战斗 Tick / 网络同步频率；
- 作用于 `weapon.fireball`（火焰弹）及遗留的 `weapon.arcane_bolt`。不修改回旋刃现有折返动画及服务端投掷物状态。

## 玩法一致性

`packages/simulation` 和服务端武器/伤害代码未修改。客户端视觉插值不参与任何碰撞、伤害、目标追踪、经验归属或爆炸触发。服务端认为弹体命中或消失时，客户端仍按原逻辑销毁该弹体，防止残留的本地“假命中”。

## 验证

新增 `tests/projectile-interpolation.test.mjs` 覆盖：

1. 10Hz 快照下计算出 60FPS 的连续中间位置；
2. 相同快照在连续帧中不会重复重置插值；
3. 新快照提前到达时按当前显示位置接续；
4. 延迟过久与异常大位移会直接吸附；
5. 客户端渲染循环真实调用新插值模块。

自动检查执行 `npm run verify`、UI 测试及真实 Colyseus 集成测试，实际结论以 GitHub Actions 当次构建为准。

## 人工浏览器检查

进入战斗观察连续多次发射火焰弹。火焰弹应当平滑向前移动，而不是每 100ms 移动一大格。尽量在正常 60Hz 显示屏下观察短程近战目标以及远处目标，确认移动连续且命中点仍与服务端伤害数字对应。若仍明显跳动，确认本地不是旧版 Vite 服务或浏览器缓存，再录制带 FPS 的实际画面核对。

本次没有通过真实浏览器进行人工视觉验收。
