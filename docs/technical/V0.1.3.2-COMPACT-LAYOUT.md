# v0.1.3.2 紧凑布局与 HUD 防遮挡修复

## 用户反馈
在手机 Safari 和小分辨率桌面浏览器下，地图缩小而生命 HUD、计时器、技能栏和摇杆仍按原尺寸叠在画布上；地图无法正常查看和操作。

## 根因
旧 v0.1.3.1 试图对战斗场景和全套 HUD 使用共同缩放；这无法同时保证横向地图纵横比、可读字体与可触摸摇杆。纵向竖屏还把场景拉成海报比例，产生无效黑区。

## 修改
1. 保持网络服务端的 **1440×810** 逻辑战场不变。
2. 提取纯布局几何计算到 `packages/shared/src/responsive-layout.ts`，按 VisualViewport、页面类型、是否战斗、输入设备类型选择布局。
3. **紧凑模式**：把 `match-hud` 与 `combat-dock` 从游戏地图覆盖层移至主布局的独立行；地图不再承担承载三个 HUD 面板和大型摇杆的空间，摇杆和冲刺继续位于地图外独立一行。正常宽屏仍保留地图内 HUD。
4. 小屏升级和结算面板脱离地图容器，固定到可见视口中央并启用内部滚动。
5. 主菜单在短而窄的窗口中独立换行排布；竖屏战斗保持 16:9 地图，不使用伪拉伸纵向地图。
6. 极矮视口若不能同时容纳所有区域，允许正常纵向滚动以保持点击尺寸和文字可读性，不再强行叠层。
7. 多组布局纯函数单元测试 + DOM 结构防回归测试。

## 人工测试矩阵
手机：320×568、390×844、667×375、844×390。
电脑：320×260 小窗口、600×400、800×600、1024×768、1366×768、1920×1080。
检查每个尺寸的主菜单、单人准备、多人房间、运行中 HUD、技能栏、摇杆、升级和结算。切换手机横竖屏、浏览器缩放，确认没有交叠、没有横向滚动条、滑动不会导致角色持续移动。微信/支付宝内置浏览器与 Safari 的行为可能不同，需真实设备验收。

CI 成功是自动化验证，不代表已通过真实移动 Safari 的图形验证。
