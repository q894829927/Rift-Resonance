# 第一章：产品定位与核心循环

## 1.1 游戏定位

《异界共振》是一款 2～4 人在线合作的弹幕生存游戏。玩家进入被异界能量侵蚀的遗迹，在持续增强的怪物浪潮中战斗，通过随机武器、被动强化及跨玩家技能共振形成独特构筑，并在最终阶段挑战 Boss。

战斗设计占比：

- 70%：高密度怪物击杀、武器成长、范围伤害与构筑爽感。
- 30%：精英敌人机制、Boss 弹幕、主动技能与多人救援。

**核心差异化：跨玩家技能共振。**

队友的构筑不再相互独立。玩家可以围绕控制、异常状态、暴击与团队增益安排武器组合，主动创造多人合作收益。

## 1.2 单局游戏循环

创建房间 → 玩家集合 → 职业选择 → 开始战斗 → 击杀怪物 → 收集共享经验 → 全队升级 → 获得新武器或强化 → 触发多人共振 → 精英战斗 → 武器进化 → 最终 Boss → 结算战绩 → 返回房间。

设计目标：

- 单局有效战斗时间：12 分钟。
- 首次明显成长反馈：开始后 60 秒内。
- 首次可用多人共振：开始后约 2～3 分钟。
- 主要武器进化窗口：6～9 分钟。
- Boss 登场：第 9 分钟。
- 结束条件：12 分钟内击败 Boss，或者全队全部阵亡。

升级选择期间暂停游戏逻辑计时，因此实际一局可能持续 13～14 分钟。

## 1.3 首版内容规模

| 模块 | V0.1 内容 |
|---|---|
| 角色 | 3 个 |
| 武器 | 6 种 |
| 武器进化 | 3 种 |
| 通用被动 | 12 种 |
| 多人共振 | 3 种 |
| 普通敌人 | 4 种 |
| 精英敌人 | 1 种 |
| Boss | 1 个 |
| 地图 | 1 张固定地图 |
| 联机 | 2～4 人合作 |
| 单局升级 | 目标约 9 次 |
| 存档 | 本地设置、个人历史战绩 |
| 排行榜 | 非首版必需 |

# 第二章：战斗系统设计

## 2.1 核心角色属性

三种角色共享同一套基础战斗规则，但具有不同的生命、机动性和初始武器。

| 属性 | 守卫 | 元素术士 | 游侠 |
|---|---:|---:|---:|
| 生命值 | 120 | 90 | 100 |
| 移动速度（像素/秒） | 150 | 160 | 175 |
| 初始暴击率 | 5% | 5% | 12% |
| 初始暴击倍率 | 1.5 | 1.5 | 1.5 |
| 冲刺冷却 | 5 秒 | 5 秒 | 4.5 秒 |
| 初始武器 | 回旋刃 | 火焰弹 | 穿透箭 |
| 主动技能冷却 | 16 秒 | 18 秒 | 14 秒 |

### 守卫

主动技能「守护战吼」：对周围敌人造成 20 点基础伤害与击退，自身获得持续 4 秒、数值为 25 的临时护盾。

专属被动「坚守」：拥有临时护盾期间，近战武器造成的伤害增加 15%。

定位：近身输出、保护队友、制造安全空间。

### 元素术士

主动技能「元素爆发」：以自身为中心释放一次范围伤害，对带有灼烧、冰冷或标记状态的敌人追加效果。

专属被动「元素延展」：自身施加的异常状态持续时间增加 20%。

定位：范围伤害、异常状态、共振启动。

### 游侠

主动技能「疾风领域」：持续 5 秒，提高自身 25% 的武器攻击频率。

专属被动「猎手本能」：连续命中相同目标时逐步获得暴击率，最多增加 15%；更换攻击目标后重新累计。

定位：持续输出、机动性、精英与 Boss 击杀。

## 2.2 移动、冲刺与伤害反馈

基础规则：

- 移动采用八方向连续移动。
- 冲刺速度约 500 像素/秒，持续 0.18 秒。
- 冲刺前 0.15 秒具有无敌效果。
- 玩家受到有效伤害后获得 0.45 秒受击保护。
- 玩家无法通过连续冲刺永久维持无敌。
- 受击反馈包含短暂闪白、伤害数字、音效与轻微镜头反馈。

玩家受击保护与冲刺无敌由服务器判定，客户端只预测视觉表现。

## 2.3 伤害计算规则

首版采用可预测、方便调试的伤害流水线：

基础伤害 → 武器倍率 → 通用伤害增益 → 暴击 → 目标防御 → 目标减伤 → 最终伤害。

计算原则：

1. 同类型百分比增益相加，不无限连乘。
2. 不同类别的增益可以按明确顺序组合。
3. 暴击在常规增益之后计算。
4. 最终伤害不小于 1，除非攻击被完全免疫或格挡。
5. 所有正式战斗伤害由服务器计算。

初版数值上限：

| 属性 | 上限 |
|---|---:|
| 普通攻击伤害加成 | +60% |
| 暴击率 | 50% |
| 暴击倍率 | 2.5 倍 |
| 冷却缩减 | 35% |
| 攻击频率增益 | +50% |
| 通用移动速度增益 | +30% |
| 通用伤害减免 | 35% |
| 同类持续伤害叠层 | 按状态单独限制 |

冷却缩减与攻击频率增益必须区分，防止同一武器通过双重加速获得超过设计预期的攻击次数。

## 2.4 武器基础数值

| 武器 | 基础单次伤害 | 攻击间隔 | 主要机制 |
|---|---:|---:|---|
| 回旋刃 | 22 | 0.9 秒 | 投掷回旋、折返追踪玩家、去程/回程命中与击退 |
| 火焰弹 | 20 | 0.85 秒 | 追踪、灼烧 |
| 冰晶碎片 | 16 | 0.75 秒 | 穿透、冰冷 |
| 静电链 | 14 | 1.1 秒 | 连锁弹射 |
| 穿透箭 | 17 | 0.55 秒 | 穿透、标记 |
| 守护法环 | 8 | 每目标 0.45 秒 | 环绕、持续接触伤害 |

说明：静电链可同时攻击多个目标，回旋刃也可以一次命中多个敌人，因此不能简单用单次伤害除以攻击间隔比较全部武器强度。

**回旋刃机制修订（2026-10）：** 玩法改为投掷型飞去来器，不再属于瞬时扇形近战。装备后优先朝附近目标方向投出；无目标时沿角色朝向投出。**每次去程都沿投掷方向飞满固定 168 世界单位才折返**，不会因命中、敌人死亡或敌人距离较近而提前返回；靠地图边缘时自动选择能完成完整射程的方向，避免边界裁切导致视觉射程变短。之后追踪玩家当前位置返回。去程/回程分别按服务端实际轨迹进行碰撞检测，同一敌人每程最多命中一次；回程伤害倍率暂定 65%（原型平衡值），沿途敌人受到击退。III 级的“覆盖扩大 25%”指飞行弧线横向摆幅扩大，**不是单次立即结算的扇形斩击**。服务端同时限制每位玩家同一时刻最多一把回旋刃在飞行。



## 2.5 战斗成长曲线

以单名玩家对常规目标的有效输出能力作为调参参考。

| 时间 | 目标输出能力 | 体验 |
|---|---:|---|
| 0～1 分钟 | 15～30 DPS | 必须主动走位 |
| 3 分钟 | 40～70 DPS | 能稳定清理小怪 |
| 6 分钟 | 70～130 DPS | 构筑开始形成 |
| 9 分钟 | 150～250 DPS | 形成显著割草爽感 |
| Boss 阶段 | 有效输出受走位影响 | 控制与输出平衡 |

DPS（Damage Per Second）指每秒伤害。这些只是同等测试条件下的调参目标，不代表所有职业都必须具有相同数值。

特别需要区分：

- 木桩 DPS：对静止目标连续攻击。
- 实战单体 DPS：考虑移动、技能覆盖与 Boss 攻击。
- 群体清怪效率：单位时间击杀数量。
- 共振贡献：由跨玩家技能组合形成的额外收益。

守卫可以拥有较低的单体木桩 DPS，但更好的近身群体输出与生存能力。

# 第三章：升级系统与随机池

## 3.1 基础构筑容量

每名玩家拥有：

- 2 个武器槽，其中一个由职业初始武器占据。
- 3 个通用被动槽。
- 1 个不可更换的角色主动技能。
- 最多将武器升级至 III 级。
- 符合条件后可以选择武器进化。
- 通用被动最多升级至 II 级。

武器和被动槽满后，不再抽出无法装备的新项目。

## 3.2 共享经验机制

所有玩家击杀怪物获得的经验进入同一个团队经验池。

当团队经验达到阈值时：

1. 当前服务器逻辑 Tick 结束后进入升级状态。
2. 停止世界时间、敌人攻击、伤害和战斗移动。
3. 每名玩家分别看到自己的三个升级选项。
4. 玩家选择结束后等待队友。
5. 最多等待 10 秒，超时按照玩家预设策略自动选择。
6. 全员完成后恢复战斗。

目标是 Boss 出场前获得约 9 次升级。

### 经验成长表

首版可采用以下逐级经验需求：

| 第几次升级 | 本级所需团队基础经验 |
|---|---:|
| 1 | 50 |
| 2 | 70 |
| 3 | 90 |
| 4 | 110 |
| 5 | 130 |
| 6 | 150 |
| 7 | 170 |
| 8 | 190 |
| 9 | 210 |

上述基础经验值以单人调试口径定义。

正式联机时，可以按照房间人数同时放大怪物刷新量和升级经验需求，目标是让不同人数的队伍拥有相近的升级时间分布，而不是四人组队时升级速度简单提高四倍。

第 9 分钟 Boss 阶段开始后不再触发新的升级暂停。剩余经验可转换为少量恢复资源，转换比例在实测后确定。

### 升级时间目标

| 升级次数 | 期望战斗时间 |
|---|---|
| 第 1 次 | 0:40～1:00 |
| 第 3 次 | 2:00～3:00 |
| 第 5 次 | 4:00～5:30 |
| 第 7 次 | 6:00～7:30 |
| 第 9 次 | 8:00～9:00 |

这里以实际击杀效率驱动升级，不强制在指定时间直接授予等级。

## 3.3 十二种通用被动

以下每种被动均占据一个被动槽。

| 被动名称 | I 级效果 | II 级效果 |
|---|---|---|
| 狂怒之心 | 普通伤害 +12% | 提升至 +22% |
| 迅捷施法 | 武器冷却缩减 8% | 提升至 15% |
| 连击技巧 | 攻击频率 +10% | 提升至 18% |
| 猎杀直觉 | 暴击率 +8% | 提升至 15% |
| 致命一击 | 暴击倍率 +0.25 | 提升至 +0.45 |
| 元素延长 | 异常状态持续时间 +20% | 提升至 +35% |
| 扩散领域 | 范围攻击半径 +12% | 提升至 +22% |
| 穿透强化 | 可穿透弹丸穿透次数 +1 | 提升至 +2 |
| 坚韧体魄 | 最大生命 +20 | 提升至 +35 |
| 紧急护盾 | 每 30 秒获得 15 点护盾 | 提升至 25 点 |
| 轻盈步伐 | 移动速度 +8% | 提升至 +15% |
| 共振增幅 | 自身参与的共振伤害 +12% | 提升至 +22% |

设计约束：

- 被动强化的最终效果始终受到属性上限约束。
- 不适用当前任何武器的强化不进入抽取池。
- 已经达到 II 级的被动不会再次出现。
- 「共振增幅」不会增加共振触发频率，只强化合格反应的伤害。
- 「穿透强化」对无法穿透的攻击不产生效果，也不进入该构筑的升级池。

## 3.4 六种武器的升级成长

| 武器 | II 级 | III 级 |
|---|---|---|
| 回旋刃 | 伤害 +20% | 投掷飞行弧线的横向覆盖扩大 25% |
| 火焰弹 | 伤害 +20% | 增加小范围爆炸 |
| 冰晶碎片 | 穿透 +1 | 冰冷积累效率提高 |
| 静电链 | 弹射次数 +1 | 弹射伤害衰减降低 |
| 穿透箭 | 伤害 +20% | 贯穿敌人后保留更高伤害 |
| 守护法环 | 增加 1 枚环绕刃 | 环绕半径及伤害提高 |

## 3.5 武器进化规则

武器进化必须满足：

1. 对应武器达到 III 级。
2. 拥有指定通用被动。
3. 当前战斗时间达到第 6 分钟。
4. 玩家尚未将该武器进化。

满足条件后，下一次升级的三个选项中保证出现该进化选项，直到玩家主动选择或本局不再发生升级。

进化占用一次升级选择，但不额外占用武器槽。

### 初版三种进化

**陨星爆炎**

- 条件：火焰弹 III + 扩散领域。
- 效果：周期性在目标区域召唤大型火焰爆炸。
- 特点：强化群体灼烧与范围清怪。
- 限制：陨星产生的范围伤害与持续灼烧分别设置命中频率限制。

**永冻风暴**

- 条件：冰晶碎片 III + 元素延长。
- 效果：周期性制造冰晶风暴，持续积累冰冷。
- 特点：强化团队控制能力。
- 限制：普通敌人的冻结有目标冷却，Boss 不接受完全冻结。

**雷霆领域**

- 条件：静电链 III + 迅捷施法。
- 效果：连续攻击多个目标，命中后有机会产生额外跳跃电弧。
- 特点：密集怪群清理能力较强。
- 限制：额外电弧不能再次无限产生电弧。

其余三种武器的进化可以在 V0.2 增加。

## 3.6 升级选项抽取规则

每次升级展示 3 个不同的有效选项。

建议采用三类候选池：

- 新武器候选池。
- 已装备武器强化与进化池。
- 通用被动新获取及升级池。

抽取规则：

1. 第一次升级保证至少包含一个可装备的新武器。
2. 到第三次升级仍未装备第二武器时，继续保证至少出现一个可用新武器。
3. 已满槽、已满级、无法发挥作用的选项被过滤。
4. 已满足进化条件的武器，在后续升级中保证至少提供一个对应进化选项。
5. 若可用候选少于三个，则展示所有有效候选，不强制塞入无效选项。
6. 每局每名玩家允许一次重抽当前选项的机会。
7. 抽取由服务器决定，并记录随机种子与选择结果。

开发初期先采用简单加权随机，不引入普通、稀有、传说等复杂稀有度。等基础构筑体验稳定后，再增加稀有度系统。

## 3.7 构筑目标示例

**火雷清怪流**

火焰弹 + 静电链 + 迅捷施法 + 扩散领域 + 共振增幅。

特点：较强的群体伤害、异常状态与超载共振。

**冰晶保护流**

冰晶碎片 + 守护法环 + 元素延长 + 坚韧体魄 + 扩散领域。

特点：降低怪物接近速度，给队友创造安全区域。

**暴击猎杀流**

穿透箭 + 回旋刃 + 猎杀直觉 + 致命一击 + 连击技巧。

特点：较高的单体爆发，偏向精英怪与 Boss。

这些是预期构筑，不是固定职业配装。玩家仍然可以在随机选项限制下自由发展。

# 第四章：多人共振系统

## 4.1 设计目标

共振机制必须同时满足：

- 容易理解，玩家可以主动创造。
- 同一玩家也能触发基本反应，方便单人调试。
- 不同玩家合作时获得明确额外收益。
- 不能产生无限连锁。
- 服务器能够确定性地计算。
- 网络延迟不能让同一次攻击重复触发。

### 触发来源

所有攻击事件拥有：

- 攻击来源玩家 ID。
- 攻击及技能 ID。
- 目标实体 ID。
- 服务器时间与逻辑帧序号。
- 伤害数值。
- 伤害标签。
- 附加状态标签。
- 是否来自共振二次伤害的标识。

共振系统只处理由正常攻击或明确允许的技能产生的事件，不直接信任客户端提交的命中结论。

## 4.2 共振一：碎裂

**触发条件：冰冷积累 + 重击。**

冰晶碎片对目标施加冰冷：

- 每次有效冰晶命中增加一层冰冷。
- 最多 3 层。
- 每层持续 2.5 秒，重新命中刷新有效期。
- 每层使普通敌人移动速度降低 12%。
- 三层时普通敌人冻结 0.6 秒。
- 同一个目标完全冻结后，3 秒内不能再次完全冻结。

重击事件能够作用于达到三层冰冷或处于冻结状态的目标，触发碎裂。

效果：

- 额外造成 45 点基础伤害。
- 对半径 75 像素内其他敌人造成 50% 的碎裂伤害。
- 消耗目标当前三层冰冷状态。
- 同一目标的碎裂内部冷却为 1.2 秒。

普通 Boss 不会被完全冻结；三层冰冷转换为可触发碎裂的裂痕状态。碎裂造成的额外反应伤害对 Boss 仅按 60% 结算。

多人强化：施加冰冷与触发重击的来源玩家不同时，碎裂伤害乘以 1.5。

## 4.3 共振二：超载

**触发条件：灼烧 + 闪电。**

火焰攻击造成灼烧：

- 持续 3 秒。
- 每秒 4 点基础伤害。
- 最多叠加 2 层。
- 不同来源的灼烧层分别保留来源信息。

闪电攻击命中具有灼烧状态的目标时，触发超载。

效果：

- 额外造成 35 点基础伤害。
- 产生 2 次短距离闪电弹射。
- 每次额外弹射造成基础超载伤害的 50%。
- 消耗目标一层灼烧。
- 同一目标超载冷却为 0.8 秒。

多人强化：灼烧来源与触发闪电的玩家不同时，反应伤害乘以 1.5。

为防止无限连锁，超载产生的额外闪电只能造成伤害，不能再次触发超载或其他共振。

## 4.4 共振三：猎杀

**触发条件：标记 + 连续有效攻击。**

穿透箭命中敌人后施加持续 3 秒的猎杀标记。

在标记生效后 2 秒内，目标再次受到累计 3 次符合条件的直接攻击命中，即可触发猎杀反应。

效果：

- 造成 60 点基础追击伤害。
- 清除猎杀标记。
- 单个目标的猎杀反应冷却为 1.5 秒。
- 连续攻击必须来自独立的有效命中事件。
- 高频持续伤害不得在一次命中内重复累计三次。

多人强化：至少有两名不同玩家参与标记与后续命中时，追击伤害乘以 1.5。

## 4.5 共振统一结算流程

一次攻击发生后，服务器按以下顺序处理：

1. 验证攻击合法性及命中。
2. 计算普通直接伤害。
3. 更新目标异常状态。
4. 检查符合条件的共振。
5. 检查同一目标、同一种共振的冷却。
6. 检查来源玩家，确定单人或多人加成。
7. 计算共振伤害及目标抗性。
8. 提交伤害和状态改变。
9. 生成一次唯一的共振事件。
10. 同步事件给相关客户端播放特效。

确定性要求：

- 同一服务器帧内的多个命中事件按照固定规则排序。
- 共振反应不能重新递归触发共振。
- 每次共振事件使用唯一标识，客户端对重复事件进行去重。
- 网络重传不应该重复结算伤害。
- 反应冷却以服务器时间为准。
- 共振伤害不会绕过常规的死亡、护盾与无敌判定。

## 4.6 共振数值平衡

建议目标：

| 指标 | 初始平衡目标 |
|---|---|
| 普通玩家独立输出 | 构成主要伤害来源 |
| 共振对团队总伤害贡献 | 约 10%～25% |
| 多人共振伤害倍率 | 基础反应的 1.5 倍 |
| Boss 反应伤害系数 | 0.6 |
| 共振触发频率 | 受目标冷却限制 |
| 多人共振视觉优先级 | 高于普通技能特效 |

共振不应该成为全队唯一的输出来源。如果实测共振伤害占比长期超过 35%，应优先检查高频触发和多目标重复结算，而不是直接提高怪物生命值。

# 第五章：敌人、怪潮与难度曲线

## 5.1 四类普通敌人

| 敌人 | 生命值 | 移速 | 伤害 | 经验 | 行为 |
|---|---:|---:|---:|---:|---|
| 裂隙虫群 | 35 | 85 | 8 | 5 | 直接追击 |
| 狂暴兽 | 95 | 100 | 18 | 12 | 蓄力冲锋 |
| 深渊法师 | 60 | 75 | 12 | 10 | 远程弹幕 |
| 裂隙卫士 | 150 | 55 | 14 | 16 | 高生命、保护附近敌人 |

以上是敌人基础数值，正式战斗中还会受到时间阶段和玩家人数的影响。

### 裂隙虫群

主要用于营造割草体验。行为简单，通常选择距离最近的存活玩家追击。

### 狂暴兽

在攻击前显示明显的冲锋预警。锁定方向后短暂延迟，再沿直线攻击。

目标是让玩家进行横向躲避，而不是依赖持续移动轻松规避全部攻击。

### 深渊法师

与玩家保持一定距离，发射速度适中、可见性较高的扇形弹幕。

一开始弹幕间隙较大，后期可通过敌人数量和攻击组合增加难度。

### 裂隙卫士

移动慢但较难清理。使用少量防御机制保护附近怪物，让控制流、持续伤害流和集中火力具有价值。

## 5.2 精英敌人：裂隙祭司

基础生命值：700。

特点：

- 周期性强化附近普通敌人。
- 定期发射小型环形弹幕。
- 自身移动速度较慢。
- 击杀后掉落少量团队恢复资源。
- 同一时刻最多允许存在有限数量的精英。

精英敌人不应单纯成为高生命值怪物，需要具有能被玩家观察并应对的特殊机制。

## 5.3 Boss：裂隙守望者

基础生命值：7000。

多人生命值缩放规则：

Boss 生命倍率 = 1 + 0.75 ×（玩家人数 − 1）。

| 人数 | Boss 生命 |
|---|---:|
| 1 人测试 | 7000 |
| 2 人 | 12250 |
| 3 人 | 17500 |
| 4 人 | 22750 |

Boss 生命缩放不直接等于玩家人数倍数，因为多人移动、技能组合和集火并不始终具有线性收益。

Boss 设计三个主要技能：

**技能一：扇形魔弹**

对目标玩家方向发射多颗魔弹，保留可观察的空隙。

**技能二：环形冲击**

以 Boss 为中心向外发射环形弹幕，带有明显安全缺口。

**技能三：地面裂隙**

提前在玩家附近标记危险范围，延迟爆发。

阶段变化：

- 100%～70% 生命：单独使用三种技能。
- 70%～35% 生命：部分技能连续释放。
- 35%～0% 生命：组合弹幕与场地危险区域。

Boss 不通过无限增加弹幕数量提高难度，重点是攻击组合、节奏和安全区域管理。

期望通关队伍的 Boss 战时间约 60～150 秒，超过范围时需要结合真实伤害记录调整 Boss 生命和机制。

## 5.4 怪物数量与难度导演

采用难度导演（Difficulty Director）控制怪物生成。

导演输入：

- 当前战斗时间。
- 存活玩家数量。
- 当前敌人数量。
- 怪物类型分布。
- 服务器实体预算。
- 已配置的阶段难度。

阶段目标：

| 时间 | 普通怪物数量目标 | 核心玩法 |
|---|---:|---|
| 0～3 分钟 | 8～20 | 入门与升级 |
| 3～6 分钟 | 20～40 | 构筑成长 |
| 6～9 分钟 | 35～60 | 大规模割草 |
| 9～12 分钟 | 15～35 + Boss | 机制战斗 |

V0.1 初始普通怪物上限设为 60 个，后续通过压力测试决定是否提高到 80～100 个。

### 多人缩放规则

基础怪物生命倍率：

1 + 0.15 ×（玩家人数 − 1）。

基础刷怪数量目标倍率：

1 + 0.50 ×（玩家人数 − 1）。

这两个系数不是最终平衡常量。设计目的是增加组队时的怪物密度与总生命，但不让四人房间变成四倍怪物数量、数倍敌人生命值的简单叠加。

怪物出场和经验获取也必须统一考虑，避免人数越多升级越快或者越慢。

## 5.5 难度平衡原则

每个时间段应有明确的战斗体验目标：

- 前 3 分钟：玩家经常需要移动，但不应因单次失误立即死亡。
- 3～6 分钟：玩家可以快速处理基础敌人，特殊敌人迫使玩家改变路线。
- 6～9 分钟：玩家可以形成明显的清屏能力，普通怪物主要承担割草体验。
- 9～12 分钟：减少不必要的普通怪物密度，让 Boss 弹幕成为主要挑战。

首轮试玩希望新手队伍具备合理通关可能性，熟练队伍可以通过配合明显提高胜率。具体胜率目标需获得足够的实测样本后再固定。

# 第六章：地图与美术规范

## 6.1 初版地图：破碎祭坛

固定地图，不进行复杂程序化地形生成。

推荐初版逻辑尺寸：2048 × 2048 像素。

地图包含：

- 中央大型祭坛。
- 四周怪物生成区域。
- 少量石柱和可绕行障碍。
- 足够开阔的战斗空间。
- 具有明确视觉反馈的 Boss 召唤区域。

地图需要保证玩家不会因为远离队友而被摄像机强制拉回。

但可以通过共享经验、救援和共振收益鼓励团队维持合理距离。

## 6.2 美术方向

整体采用：

**像素角色 + 像素地图 + 现代粒子特效 + 清晰的高分辨率 UI。**

角色基础美术尺寸建议采用 32×32 像素规格，实际绘制范围允许根据武器与职业扩展。

视觉规范：

| 元素 | 视觉方向 |
|---|---|
| 玩家角色 | 清晰轮廓与职业识别 |
| 普通敌人 | 暗色、低饱和度 |
| 火焰 | 橙红色 |
| 冰晶 | 青蓝色 |
| 雷电 | 紫色 |
| 友方治疗 | 绿色 |
| 敌方危险弹幕 | 高对比红色与明确轮廓 |
| 多人共振 | 大尺寸短时反馈，不遮挡玩家 |

必须支持降低粒子数量、关闭强烈震屏等选项。

## 6.3 画面层级

游戏渲染层包括：

1. 地形和背景装饰。
2. 地面危险预警。
3. 玩家、敌人与可拾取物。
4. 武器和技能效果。
5. 必须保持清晰的敌方危险弹幕。
6. 共振提示及重要战斗反馈。
7. 血条、技能栏、团队状态和升级界面。

华丽特效可以遮挡普通背景装饰，但不能遮挡玩家角色轮廓、关键危险区域与交互提示。

## 6.4 性能画质分级

高画质：完整粒子、拖尾、发光、震屏。

中画质：降低粒子数量与发光强度。

低画质：保留必要攻击形状和危险提示，关闭非必要特效。

设计目标为桌面浏览器在适当硬件上维持 60 FPS，不能将其误认为所有设备均可保证达到的性能。

# 第七章：多人联机规则

## 7.1 房间机制

- 2～4 人合作房间。
- 通过房间码或邀请链接加入。
- 玩家输入昵称后即可加入，不要求注册账号。
- 由创建房间的玩家开始游戏。
- 战斗开始后禁止普通新玩家加入。
- 创建者退出后游戏仍能继续。
- 全部玩家离线超过合理保留期限后销毁房间。

## 7.2 掉线重连

- 每个玩家具有服务器分配的会话身份。
- 连接中断后保留席位约 60 秒。
- 重连时校验会话身份。
- 重连成功后恢复位置、生命、武器、升级与其他必要状态。
- 重连期间角色停止输入，不能通过断线获得无敌或规避伤害。
- 超时则转入离线状态，不再允许任意人占用原有角色。

首版需要明确测试重连时升级状态、倒地状态与 Boss 战状态的恢复。

## 7.3 倒地与救援

- 玩家生命为零后进入倒地状态。
- 倒地后无法正常攻击和移动。
- 队友靠近后持续交互 2.5 秒。
- 受到有效伤害时救援中断。
- 救援成功后恢复 35% 最大生命。
- 复活后获得 2 秒保护。
- 全队共享 3 次成功救援机会。
- 所有玩家倒地且无人具备可执行救援能力时，战斗结束。

救援判定以服务器为准，客户端只显示交互进度。

## 7.4 游戏公平与同步

服务器权威处理：

- 玩家合法位置。
- 技能与冲刺冷却。
- 敌人 AI。
- 弹幕命中。
- 生命、护盾、死亡。
- 经验与升级。
- 武器进化。
- 共振触发。
- Boss 战阶段。
- 结算战绩。

客户端处理：

- 输入采集。
- 本地移动预测。
- 远端实体插值。
- 动画、粒子、音效。
- 伤害数字与交互 UI。

客户端不能直接决定击杀结果或修改武器等级。

# 第八章：服务端与网络技术设计

## 8.1 技术选型

| 模块 | 技术方案 |
|---|---|
| 游戏客户端 | Phaser + TypeScript |
| 游戏服务端 | Node.js + Colyseus |
| 联机传输 | WebSocket |
| 静态资源服务 | Nginx |
| 数据库 | 首版可不使用；后续 SQLite |
| 操作系统 | Alibaba Cloud Linux 4 |
| 部署服务器 | ECS 2 核 2G |
| 服务管理 | systemd |
| 版本管理 | Git |

核心游戏逻辑与玩家渲染分离。

后端可以直接运行在 ECS 上，不需要服务器显卡。

## 8.2 更新与同步频率

首版采用：

- 客户端目标渲染：60 FPS。
- 服务器固定战斗逻辑：20 Tick/s。
- 状态同步：10 次/秒。
- 玩家输入：约 10～20 次/秒，并根据输入变化优化。
- 远端玩家与敌人使用插值平滑。
- 本地角色采用预测与服务器状态校正。

这些参数应能在后续压测中调整，不应该硬编码成难以修改的固定行为。

## 8.3 弹幕同步策略

必须严格区分：

**逻辑弹幕**

可以造成伤害，需要服务器计算轨迹、有效期和命中。

**视觉弹幕**

只有视觉效果，不参与服务器伤害判定，可以由客户端根据技能事件重建。

对于规则明确、轨迹可推导的弹幕，服务端广播发射事件及必要参数，客户端根据统一时间基准重建显示。

不得将全部逻辑命中判定交给客户端。

## 8.4 实体预算

V0.1 首个性能目标：

| 实体 | 目标上限 |
|---|---:|
| 玩家 | 4 |
| 普通敌人 | 60 |
| 精英 / Boss | 按阶段限制 |
| 服务端有效伤害弹丸 | 120 |
| 客户端装饰粒子 | 按画质分级控制 |
| 活跃房间 | 先验证 1 间 |

重点优化：

- 空间网格与邻近查询。
- 圆形、矩形等简化碰撞体。
- 简化怪物追击行为。
- 批量计算状态伤害。
- 避免大量短生命周期对象分配。
- 限制每 Tick 的工作量。
- 网络状态增量同步。
- 玩家视野范围内的实体优先同步。

## 8.5 性能验收

单个四人房间的首轮性能标准：

| 指标 | 验收目标 |
|---|---|
| 游戏逻辑 Tick 频率 | 稳定接近 20 Hz |
| Tick 耗时 P95 | 小于 25 ms |
| Tick 耗时 P99 | 尽量小于 45 ms |
| 服务端内存 | 不发生持续无界增长 |
| 客户端渲染 | 常见桌面设备目标 60 FPS |
| 战斗状态 | 服务端唯一权威结果 |
| 断线重连 | 正确恢复游戏状态 |
| 连续运行 | 能完成至少 30～60 分钟测试 |

由于服务器只有约 1.6 GiB 的系统可见内存，需要监控系统基础进程和 Node.js 占用，并为异常内存增长设置保护措施。

## 8.6 公网带宽预算

如果 ECS 使用 3 Mbps 峰值公网带宽，所有玩家共享这一出口。

首轮设计希望四人房间平均公网出站流量控制在约 20～60 KB/s 的量级。

该范围属于待测的工程预算，实际取决于怪物数量、增量包大小、同步频率、协议开销和客户端资源加载。

需要在测试中分别测量：

- 房间空闲时的网络流量。
- 两人战斗期间的网络流量。

# 第十章：开发里程碑

以下以单人主导开发、利用现成框架和基础美术资源为假设。时间是估算，不能视为交付承诺。

## M0：基础技术验证（预计 1 周）

目标：证明技术栈能够正常运行。

内容：

- 创建 Phaser 客户端工程。
- 创建 Colyseus 服务端工程。
- 建立玩家输入、服务器 Tick 与状态同步。

两名客户端连接同一房间，能够观察彼此移动；客户端不能直接修改服务端位置状态。

## M1：核心战斗原型（预计 1～2 周）

目标：确认基础战斗具有可玩性。

内容：

- 玩家移动、冲刺、受伤与死亡。

- 两种基础武器。
- 两种敌人。
- 最基础的怪物生成。
- 基础碰撞和伤害系统。
- 开发用的战斗统计和调试显示。

验收：

能够完成 3～4 分钟的基础生存战斗，没有明显的伤害重复计算或对象泄漏。

## M2：多人联机垂直切片（预计 2 周）

- 倒地与救援。
- 简化战斗结算。

验收：

两名玩家在不同电脑上完成一局 4 分钟游戏，状态一致，网络波动后能够恢复或明确结束连接。

## M3：构筑系统（预计 2 周）

## M4：地图、精英与 Boss（预计 2 周）

双人及四人队伍都能从创建房间进入完整战斗并完成胜负结算。

# 第十一章：测试、平衡与数据回收

## 11.1 核心测试类型

**规则测试**

- 攻击和伤害是否重复结算。
- 同一目标的共振是否遵守冷却。
- 玩家掉线时状态是否一致。
- 升级池是否出现非法选项。
- 武器槽与被动槽是否超出上限。
- 多人救援是否正确消耗次数。

**玩法测试**

- 初始角色是否都具有独立生存能力。
- 不同武器是否有明确使用价值。
- 共振是否值得主动配合。
- 是否存在长期占优的固定构筑。
- Boss 攻击是否清晰、可躲避。

**性能测试**

- 不同怪物数量下的 Tick 耗时。
- 大量弹幕下的碰撞成本。
- 高频异常状态带来的计算负担。
- 四人房间的网络带宽。
- 连续多局后的内存变化。

## 11.2 重点采集指标

每局至少记录：

- 房间人数。
- 最终结果和游戏时长。
- 各角色伤害量。
- 武器选择率。
- 武器进化率。
- 升级池选项出现率与选择率。
- 玩家死亡及救援次数。
- 共振触发次数和伤害贡献。
- 怪物平均击杀时间。
- Boss 战时长。
- 服务端 Tick 耗时。
- 房间网络流量。

首轮每次调整只修改少量相关变量，避免同时改变怪物生命、武器伤害、经验和刷怪速度，导致无法判断平衡变化的来源。

## 11.3 数值调整优先顺序

1. 玩家移动和冲刺手感。
2. 基础攻击的命中反馈。
3. 前三分钟怪物密度和生存压力。
4. 升级节奏。
5. 普通武器之间的相对强度。
6. 共振收益。
7. 精英与 Boss。
8. 多人缩放与最终难度。

不要在基础战斗手感尚未验证时大量调整后期 Boss 数值。

# 第十二章：首版范围控制与风险

## 12.1 首版明确不做

- PvP 玩家对抗。
- 大型开放地图。
- 程序化随机地形。
- 复杂永久装备养成。
- 玩家间道具交易。
- 公会、聊天大厅和天梯。
- 多地图章节。
- 付费系统。
- 完整移动端适配。
- 分布式多服务器集群。
- 大量需要服务端逐个同步的视觉粒子。

## 12.2 主要项目风险

| 风险 | 影响 | 应对方式 |
|---|---|---|
| ECS CPU 不足 | 怪潮时掉 Tick | 先限制实体上限，测量热点 |
| ECS 内存不足 | 进程异常退出 | 限制缓存、监控内存、按需配置 Swap |
| 公网带宽较低 | 联机延迟与抖动 | 增量同步，减少冗余状态 |
| 共振规则过于复杂 | 重复伤害与难维护 | 统一事件流水线和冷却规则 |
| 升级系统随机性过强 | 构筑无法成型 | 候选过滤与必要保底 |
| 特效遮挡弹幕 | 玩家难以识别危险 | 危险信息优先及画质分级 |
| 开发内容过多 | 项目长期无法完成 | 严格按 M0～M5 验收推进 |

## 12.3 发布边界

开发和私人联机测试阶段先确保房间访问受控，避免开放未经过安全验证的管理接口。

由于服务器在中国内地，正式以网站形式向公众开放前，需要处理域名、ICP备案以及适用的网络游戏运营与内容合规事项。

# 第十三章：最终验收定义

V0.1 被视为完成，必须满足：

- 支持 2～4 人通过浏览器加入同一房间。
- 玩家可以完成完整 12 分钟战斗。
- 三种职业、六种武器可正常使用。
- 十二种被动及升级选项符合规则。
- 至少三种跨玩家共振能够稳定触发。
- 所有伤害、状态、升级和死亡由服务器权威结算。
- Boss 具备完整阶段和技能。
- 断线重连不会破坏房间状态。
- 游戏结束能够展示每名玩家的战绩。
- 完成 ECS 的四人性能与流量测试。
- 游戏能够在目标桌面浏览器上正常运行。

**V1.0 GDD 的核心目标不是提前完成所有创意，而是定义一个真正能在现有硬件上实现、能和朋友完整游玩，并且后续有明确扩展空间的版本。**
